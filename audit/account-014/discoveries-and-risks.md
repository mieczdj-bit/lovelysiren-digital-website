# Pass 014 — Significant discoveries and cross-project risks

## Confirmed defects or constraints

- **Confirmed safe-packaging gap addressed:** the Pass 013 account API export included `preferences/read` and `preferences/update` routes even though those features were emulator-fixture gated. Pass 014's generated first-registration package removes both routes and all contact-preference/address mutation code; it also omits the contact delivery export and deletion/cleanup modules. The source service defaults remain closed.
- **Confirmed rules-review incompatibility fixed:** `scripts/prepare-account-rules-review.cjs` allowed only the pre-Pass 013 groups and would reject the approved Google enrollment indexes. The expected paths now include `googleEnrollmentGrants` and `googleEnrollmentReservations`. Live rules still must be freshly captured and manually reviewed.
- **Confirmed published Privacy mismatch:** `privacy.html` is the published combined website/RTA policy, while account readiness requires an approved Website/Account Privacy version and a separately preserved RTA disclosure. The proposed drafts cannot replace the live combined page without both approvals and the reviewed transition.
- **Confirmed code status:** public account client flags remain disabled, policy privacy version is null/unapproved, contact delivery is hard inactive, marketing preferences are restricted to a demo emulator fixture, identity resolver remains independently gated, and deletion coordinator is not exported. No production permission/API/user was inspected in Pass 014.
- **Confirmed current-source evidence boundary:** RTA conflict findings are pinned to old commit `048c0138f7c99a2bc8c59a317ff87ca74afbd7c2`. They are not current-source claims. The RTA Producer must inspect the present branch/commit before changing the adapter or approving game-policy descriptions.

## Release risks and unresolved decisions

- **Confirmed prior shared-database exposure risk; candidate boundary changed:** the prior implementation used Firebase Admin against the existing default RTDB, where a namespace path alone does not scope IAM. Pass 014 candidate now refuses the default database URL, requires a separate account-only RTDB instance, and sets Admin SDK `databaseAuthVariableOverride` to `lovelysiren-account-service`; fresh reads use the scoped SDK so rules apply. This is a code-level mitigation, not a verified infrastructure boundary: the instance and rules do not exist, the runtime identity is a proposed unprovisioned name, and effective IAM/rules behavior still requires isolated staging tests. Do not point this candidate at the RTA database.
- **Firebase provider coexistence:** email/password client sign-in and existing Google identities share the RTA Firebase Auth project. Current provider toggles, OAuth clients, Auth domains/templates and users must be freshly inspected. Do not enable/disable/reconfigure Google or email/password without an approved review of RTA effects.
- **Privacy claims need owners/evidence:** support inbox retention, provider logs/backups, optional contact field necessity, adult-eligibility security records, data-rights handling, AdMob/child treatment and Play purchase behavior require operational/Producer/legal review. No fixed retention schedule or legal compliance certification is asserted.
- **Unexpected Google account side effect:** selecting a previously unseen Google identity can create a Firebase Auth user before the company server rejects UID mismatch. The test operator must verify the invited UID first; unexpected Auth users require careful reconciliation and must not be automatically deleted.
- **No complete deletion:** company deletion controls are not ready and RTA's trusted deletion API remains planned/not implemented/not deployed. Do not perform account closure or claim complete deletion for an RTA-linked person.
- **Deployment collision risk:** Firebase Functions names are project-wide. The candidate uses a distinct `lovelysirenAccounts014Api` export and a named codebase, but no live v1/v2 inventory was taken. Stop if a current function name, codebase, region or URL collides.
- **Candidate service-account label is only proposed:** `lovelysiren-accounts-staging@road-trip-arcade.iam.gserviceaccount.com` is a package placeholder, not a verified existing principal or approved grant. Confirm existence/name/roles before deployment; never create a key.
- **Staging host is only proposed:** `accounts-staging.lovelysirendigital.com` has not been created, DNS-verified, authorized in Firebase Auth or tied to email actions. Production origin and root DNS must not be reused for test configuration.
